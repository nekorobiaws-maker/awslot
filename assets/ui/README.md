# 筐体UI画像の置き場

ここに置いた PNG は起動時に読み込まれ、筐体・リール・液晶の見た目に使われます。
**画像が読めなかった場合は、それぞれ従来の CSS / プロシージャル描画へ自動でフォールバック**
するので、ファイルを消してもゲームは壊れません(絵柄PNGと同じ流儀)。

読み込み対象は `src/engine/assets.js` の `UI_ASSETS`(存在リスト)で管理しています。
**PNGを増やしたら `UI_ASSETS` にも追記**してください。リストにあるファイルだけを
fetch するので、未配置のファイルへのリクエスト＝コンソールの 404 が発生しません。

### Canvas を載せる窓(絵の窓 → Canvas表示座標)

`engine/layers.js` の `setLayerViews()` で **表示位置・表示サイズだけ** を差し替えます。
**Canvas内部の論理座標系(液晶440×300 / リール360×180 / HUD360×60)は不変**なので、
各Viewと演出アニメの描画コードは無改修です。窓の縦横比は上のバンド表で
論理比とぴったり一致するように作ってあるため、**引き伸ばしゼロ**で載ります。

| Canvas | 元絵の窓 (x0,y0)–(x1,y1) | 表示矩形 (left, top, w, h) | 表示倍率 | 比の誤差 |
|---|---|---|---|---|
| `#lcd` | (214,174)–(874,582) | 111.5, 109.4, 501.6×342.0 | ×1.140 | 0.00% |
| `#reels` / `#reelfx` | (307,656)–(775,872) | 182.2, 506.6, 355.7×177.8 | ×0.988 | 0.00% |
| `#hud` | (405,900.5)–(775,962.2) | 256.6, 706.1, 281.2×46.9 | ×0.781 | 0.05% |

HUD は操作デッキの黒い凹み(データ表示窓)に載せています。液晶とリールの間の
金属帯にも同じ比で収まりますが、そこへ置くと液晶の黒とつながって1枚の大きな
黒面に見え、リール窓の上枠が消えてしまいます。

元絵の開口の実測値(2026-08-14 の正アートで計測。2026-08-15 のルナ版でも同じ)は
液晶が `x216..872 / y176..580`、リールが `x307.5..774.5 / y659.5..869.5`
(3窓の内訳は R1 `307.5..443.5` / R2 `473.5..609.5` / R3 `639..774.5`)、
HUD の凹みが `y888..965` です。液晶の窓は**開口の2px外側**に取っています
(そこは元絵でも黒縁なので、はみ出しても黒が黒になるだけ。逆に内側へ取ると
端数の丸めで焼き込みアートが1px覗きます)。リールの窓も開口よりわずかに大きめです。

**ルナ版(2026-08-15)の液晶は黒無地**なので、焼き込みアートが無くなったぶん
黒い面が `x≒186..898 / y≒171..588` まで広がっています。ただしその中心 `(542, 379.5)` は
窓の中心 `(544, 378)` とほぼ一致するため、**窓は据え置き**にしました。黒面いっぱいに
広げるには `712:417 ≒ 1.71` という横長比が要り、液晶Canvasの論理比 `440:300 = 1.4667`
と合わない(＝広げるならバンドの再配分になり、リール以降が全部動く)ためです。
差の**左右≒20px / 上下≒3px は黒の上に黒が乗るだけ**で、実機ではベゼルに見えます。

### レバーが左右2か所ある理由

実機の流儀に合わせて **レバーは左が正**(ユーザー指示)。
cabinet2.png は絵のレバーが右側にあるため、右のヒットエリアも
「絵にレバーが描かれているのに押しても反応しない」を避ける補助として残してあります。
どちらを押しても `LEVER` で、キーボード(Space / ↑)は不変です。

読み上げとフォーカスは左に一本化しています(右は `aria-hidden` + `tabindex="-1"`)。
左のヒットエリアは `render/cabinet.js` が起動時に生成し、位置は
`style.css` の `#cabinet.art-cabinet2 .lever-left` が持ちます。
元絵の黒球ノブ `(200,983)-(268,1057)` を横0.76倍・操作デッキ帯0.760倍で写した位置です。
旧筐体(`cabinet.png`)は元からレバーが左にあるので、この追加ヒットエリアは出ません。

右レバーは絵の右端ギリギリ(球の右端が論理x=718)なので、ヒットエリアの幅を
43pxに抑えて 720 に収めてあります。横倍率 0.76 はこの制約から決めた上限値です。

MAX BET は絵に文字が印字済みなので、DOM側の `.cap` は CSS で隠しています。
停止ボタンのキー表記(A/S/D)は矢印キー主体の操作系になったため出していません。

## 生成しなおすときの注意

- すべて**透過PNG**で書き出すこと(筐体の外周の光が背景に溶けます)
  ただし `cabinet2.png` だけは**グリーンバックのままでも可**(下の節を参照)
- `cabinet.png` は縦横比 2:3 (1024×1536) を維持すること
- 窓(液晶/リール/HUD)は**真っ黒な凹み**として描くこと。Canvas がその上に乗ります
- `reel_frame.png` は元絵に右辺がありません。`render/reelview.js` が
  左辺・左角を水平反転して右側を作る9スライス合成をしています

### グリーンバックの筐体画像を置く場合(cabinet2.png)

**2026-08-14 から、緑背景のまま置いて構いません。**
`render/cabinet.js` が読み込み直後に一度だけ走査して緑を抜きます
(`CABINET2_CHROMA` / `keyOutGreen()`。1086×1448 で約10ms、以後はキャッシュ)。
画像を差し替えるたびに手で抜き直す必要がないよう、ランタイム処理にしてあります。

判定は **緑度 = `G - max(R, B)`**。筐体は紫・オレンジ・クロムだけでできていて
緑度が正の画素をほとんど持たないので、単純なしきい値で狙い撃ちできます。

| 値 | 既定 | 役割 |
|---|---|---|
| `hard` | 40 | この緑度以上は完全に透明(RGBも0にして、縮小の補間で緑が混ざらないようにする) |
| `soft` | 6 | `soft`〜`hard` は緑の混ざり具合に応じて半透明。輪郭のアンチエイリアスになる |
| `minG` | 12 | これより暗い画素は触らない(黒い影は筐体側なので残す) |
| `spill` | 6 | 半透明にした画素の `G` を `max(R,B)+spill` で頭打ちにして、緑かぶりのにじみを消す |
| `keep` | 矩形の**配列** | この矩形の中だけ走査しない。「絵として描かれた緑」を守るための穴 |

`keep` で守っているのは3か所です。

| 矩形 | 中身 | 守らないとどうなるか |
|---|---|---|
| 液晶窓 `(214,174)–(874,582)` | ルナ版は黒無地なので緑は無い。サメ版で必要だった枠を**将来また焼き込みアートが来たとき用に残してある**(実害なし) | (サメ版では液晶の緑のAWSアイコンが四角く抜けた) |
| `(832,836)–(886,886)` | **INVENT METER の緑セグメント**(ルナ版の実測 `x839..879 / y838..880`) | メーターの下3目盛りが四角く抜け落ちる |
| `(170,1066)–(912,1322)` | **下部パネル全面**(2026-08-15 追加)。**S3バケツの緑六角**(実測 `x241..313 / y1154..1236`)と、光条にある緑がかった1px幅の筋(`x308 / x380 / x887` あたり) | S3アイコンが六角ごと四角く抜け落ち、パネルに細いスリット状の穴が空く |

六角ひとつを囲うのではなくパネルの枠ごと守っているのは、細い筋まで一緒に守れて
**パネルの中には背景の緑が1画素も無い**(連結成分で数えて0)ためです。
広く取っても抜け残りは増えません。

**元絵を差し替えたら、緑のパーツが増えていないか必ず確認してください。**
INVENT METER の緑は 2026-08-14 の差し替えで、S3バケツの緑は 2026-08-15 の
ルナ版で増えたものです(最初は液晶窓ひとつで足りていました)。
確認は「緑度 `G-max(R,B)` が `soft` を超える画素を連結成分に分け、
画像の外周につながる成分＝背景、それ以外＝絵として描かれた緑」と見るのが確実です。

`keep` があるおかげで連結成分をたどる必要がなく、**レバーと筐体の隙間のように
「囲まれた緑」も正しく抜けます**。緑が画像面積の2%に満たない場合は
「グリーンバックではない」とみなして元の絵をそのまま使うので、
透過PNGを置いても(`cabinet2_old_ghost.png` のように)そのまま動きます。
現行の `cabinet2.png`(ルナ版)では画像の 25.7% が完全透過されます。
実機の `#cabinet-art` を読み出して検算したところ、**`keep` の外に残った緑は 0px**、
背景側の代表点(左外・右外・上外・左下外・右下外・レバーと筐体の隙間)は
すべて `alpha=0`、逆に `keep` の中では INVENT METER と下部パネルの緑が
そのまま残っていました(画像の上端・左端・右端の抜き残しも 0px。
下端は台座が画像の底辺に接しているため残ります)。

自分で透過PNGを作って置く場合は、単に緑を透明にするだけだと**縮小時に緑のフチが出ます**。

1. **透明画素のRGBが緑のまま** → 縮小の補間で緑が混ざる
   不透明画素の色を透明側へ数px にじませて(dilate)から書き出す
2. **クロームの縁が背景の緑を反射している(スピル)**
   `G` が `max(R,B)` を大きく超える画素だけ `G` を抑える
3. 抜きマスクが二値だとフチがギザつくので **alphaを0.6pxだけぼかす**

の3点が要ります(バックアップの `cabinet2_old_ghost.png` はこの手順で作ったものです)。
