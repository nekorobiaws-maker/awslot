# JAWSLOT -ジョースロット-

> **クラウドは、勝手にスケールする。**
> AWSサービスを積み上げて、止まらないアーキテクチャを組み上げるパチスロ。

> 台名は 2026-08-15(U45)に「AWSLOT — オースロット」から改名しました。
> **画面に出る文言だけ** が新しい名前で、コード側の識別子(`window.AWSLOT` /
> CSS の id・class / ディレクトリ名 `awslot/`)はすべて据え置きです。

ビルド不要・外部ライブラリなしの ES モジュール製スロットです。
設計は [`docs/DESIGN.md`](docs/DESIGN.md) を参照してください。

現在は **Phase 0 〜 Phase 6** まで実装済みです(全16モード / 演出64本 / 効果音60種 + BGM6曲)。
絵柄PNGとキャラ音声MP3は未同梱で、どちらも無くてもプレースホルダ描画・無音で問題なく遊べます。

## 起動方法

ES モジュールは `file://` から読み込めないため、必ず静的サーバ経由で開きます。

```bash
cd awslot
node scripts/serve.mjs
# → http://127.0.0.1:8123/ をブラウザで開く
```

ポートを変えたい場合は `node scripts/serve.mjs 9000` のように指定します。
Node は標準モジュールしか使っていないため、`npm install` は不要です。

## 操作方法

| 操作 | マウス / タッチ | キーボード |
|---|---|---|
| MAX BET(3枚投入) | 左下の丸ボタン | `Enter` |
| レバーON(回転開始) | 右のレバー | `Space` |
| 左リール停止 | 左の停止ボタン | `A` |
| 中リール停止 | 中の停止ボタン | `S` |
| 右リール停止 | 右の停止ボタン | `D` |
| 分岐の選択(左 / 右) | 左 / 右の停止ボタン | `A` / `D` |
| 音のミュート切替 | — | `M` |

1ゲームの流れは **MAX BET → レバーON → 停止×3 → 払出** です。
クレジットが足りなくなると自動で 50 枚投入されます(プロトタイプ用の挙動)。

**分岐選択**: Step Functions ゾーンでは「どちらのステートへ進むか」を聞かれます。
リールが止まっている間だけ停止ボタンが選択ボタンを兼ね、左(`A`)/ 右(`D`)で選びます。
どちらを選んでも成功率は同じで、8秒放置すると自動で左が選ばれるため進行が止まることはありません。

### 音について

ブラウザの自動再生制限があるため、**最初のクリックまたはキー操作で音が鳴り始めます**。
効果音・BGM ともに Web Audio でその場で合成しているので、音声ファイルの準備は不要です。
`M` キーで効果音・BGM・キャラ音声をまとめてミュートできます(設定はリロードで既定に戻ります)。

## デバッグ機能

### キーボード

| キー | 内容 |
|---|---|
| `↑` | **状態で自動判別**(BET前=MAX BET / BET後=レバーON / リザルト中=もう一度) |
| `←` `↓` `→` | 左 / 中 / 右リールを停止 |
| `R` | リザルトから新しい100回転を開始 |
| `1` | 弱チェリー(IAM)を強制成立 |
| `2` | 強チェリー(IAM金)を強制成立 |
| `3` | スイカ(S3)を強制成立 |
| `4` | チャンス目(Lambda)を強制成立 |
| `5` | ベル(EC2)を強制成立 |
| `6` | リプレイ(DynamoDB)を強制成立 |
| `7` | サメ揃い(BAR)を強制成立 |
| `8` | ゴースト揃い(幽霊7)を強制成立 |
| `9` | リプレイ2(Route 53)を強制成立 |
| `-` | Bedrock(生成AI)を強制成立 |
| `0` | クレジット +50 |
| `M` | ミュート切替 |
| `Z` `X` `C` `V` | RUSH 4種へ強制突入(オートスケーリング / CloudFront / Aurora / ヒーロー) |
| `H` | 画面下のデバッグ凡例の表示切替 |

矢印キーだけで一通り遊べます(`↑` でベット → もう一度 `↑` で回す → `←` `↓` `→` で停止)。
`Enter` / `Space` / `A` `S` `D` も従来どおり使えます。

強制成立は **次の1ゲームだけ** 有効です(押してからレバーON)。
`4`(チャンス目)と `7`(サメ)は **押した次のゲームでCZ突入が確定**します(U72)。`7` はさらに RUSH直撃 0.85%、`8`(ゴースト)はボーナス確定なので、
モード遷移をひととおり見たいときに便利です。
`8` を押した場合は入賞待ち(「ゴースト7を揃えろ!」)に入るので、
そのまま数ゲーム回して図柄を揃えるとボーナスが始まります。
`9`(リプレイ2)は払出のみの小役です。`-`(Bedrock)は特殊役で、U72 からは**ステージ昇格(高確 24% / 激アツ 7%)専任**になりました(CZ抽選は持ちません)。

### URLパラメータ

| パラメータ | 内容 |
|---|---|
| `?turbo=1` | 3倍速。`?turbo=8` のように倍率指定も可(上限10) |
| `?seed=12345` | 乱数シードを固定して再現可能にする |
| `?mode=AS_RUSH&dc=5` | 指定モードから開始(下記21モードすべて指定可。`?dc=` はオートスケーリングRUSHの初期台数) |
| `?debug=1` | EventBus の全イベントと演出シナリオの選択をコンソールに出力 |
| `?nofx=1` | 演出システムを停止(素のゲーム進行を確認したいとき) |

`?mode=` に指定できるモードID(`BONUS` を指定した場合も入賞待ちから始まります):
`FREE_TIER` `CZ` `BONUS_READY` `BONUS` `HOT_STANDBY` `ROUTE53_FAILOVER` `RESULT`
RUSH 4種: `AS_RUSH` `CF_RUSH` `AURORA_RUSH` `HERO_RUSH`
`SPOT_ZONE` `EC2_BURST` `GRAVITON` `RESERVED`
`CLOUDFRONT` `KINESIS` `STEP_FUNCTIONS`
`SERVERLESS_RUSH` `MULTI_REGION` `REINVENT_ED`

例: `http://127.0.0.1:8123/?turbo=1&seed=42&mode=AS_RUSH&dc=6`

### ブラウザコンソール

`window.AWSLOT` から `flow` / `modes` / `credit` / `reels` / `rng` / `director` / `timeline` / `chars` / `audio` / `voice` に触れます。

### ヘッドレス自動試行

ブラウザを使わずに大量ゲームを回してバランスを測ります(描画も演出も読み込みません)。

```bash
node scripts/sim.mjs 300000 12345      # ゲーム数 シード
node scripts/sim.mjs 300000 12345 --baseline   # Phase 5 の追加要素だけ止める
node scripts/sim.mjs 300000 12345 --phase3     # 改修前(Phase 3 相当)の機械割
```

機械割・初当り・モード別滞在に加えて、リール配列の5コマ窓制約、モードスタック深さ、
統計的に出にくい経路(天井→W-A確定、SFN全制覇→MULTI_REGION、100回転→買い取り→リザルトなど)
まで検証して PASS/FAIL を返します。

```bash
node scripts/sim.mjs --session=10000        # 100回転セッションを1万回試行してスコア分布を出す
node scripts/sim.mjs --session=10000 777    # シード指定
```

セッションモードでは平均/中央値/上位1%スコア、ボーナス遭遇率、RUSH 4種の平均獲得、
買い取りの発生率までまとめて実測できます。

## モードの流れ(全18モード)

```
FREE_TIER ─チャンス目 = CZ確定─> CZ(11種) ─突破─> BONUS_READY ─揃った─> BONUS(3種)
  │  内部状態3段階 / 天井78G        │            「7を揃えろ!」            │
  │  (天井到達で W-A CZ 確定)       └─失敗─> FREE_TIER                    │消化中の子役でRUSH抽選
  └──────────(直撃 / レバーONフリーズ)─────────────────────┐        │
                                                            ▼        ▼
                                              RUSH 4種(伸びる軸が1本ずつ)
                                              AS / CloudFront / Aurora / ヒーロー
              ┌──────────────────────────────────────────────┤
              │ 派生ゾーン(親の上に積まれ、終了で親へ復帰)      │ 消化しきる
              │  SPOT_ZONE / EC2_BURST / GRAVITON / RESERVED  ▼
              │ 上乗せ特化ゾーン                          HOT_STANDBY(5G / 引き戻し55%)
              │  CLOUDFRONT / KINESIS / STEP_FUNCTIONS      │成功→RUSHへ復帰
              │ 上位AT                                      │失敗
              │  SERVERLESS_RUSH ──> MULTI_REGION           ▼
              └────────────────────────────────────────> FREE_TIER

  差枚+1500 または ATセット4 到達 ──> REINVENT_ED(5G)──> FREE_TIER へリセット
```

モードスタックは**深さ3まで**(例: `AS_RUSH > SPOT_ZONE > CLOUDFRONT`)。
4段目を積もうとした場合はガードが働き、深さ3を超えません。

### 突入経路

派生ゾーンは **オートスケーリングRUSH 中にレア役を引いたとき**だけ抽選されます
(下表の数値は「その役を引いたときの振り分けウェイト」で、合計が 1.00 未満なら残りは非当選)。

| モード | 突入経路 |
|---|---|
| `BONUS_READY` 入賞待ち / 平均約1.7G | ボーナス当選(CZ突破・直撃・フリーズ)すると必ずここを経由 |
| `SPOT_ZONE` 純増16枚 / 最低6G保証 | サメ揃い 0.30 / ゴースト 0.30 |
| `EC2_BURST` 初期クレジット60 / 毎G-5 | サメ揃い 0.25 / 強チェリー 0.045(レア役で回復・上限90) |
| `GRAVITON` 純増6枚 / 1セット8G / 継続72% | チャンス目 0.03 |
| `RESERVED` 1年+5G / 3年+10G | 強チェリー 0.025(3年は激アツ) |
| `CLOUDFRONT` 8G固定(1G 0〜60枚) | スイカ0.075 / チャンス目0.095 / 強チェリー0.095 |
| `KINESIS` シャード数ぶん(1本 5〜60枚) | スイカ0.05 / チャンス目0.065 / 強チェリー0.07 / サメ0.20 |
| `STEP_FUNCTIONS` 5ステート | 強チェリー0.015 / サメ揃い 0.25 / ゴースト 0.50(全制覇で MULTI_REGION へ) |
| `SERVERLESS_RUSH` | 6セット連続継続 / サメ揃い0.30 / ゴースト0.20 |
| `MULTI_REGION` | SERVERLESS中のゴースト / SFN全制覇 |
| `HOT_STANDBY` 5G(レア役で+1G / 上限15G / 実測 平均5.8G) | RUSHを消化しきると必ず経由。成功**55%**で復旧のゴーストボーナスSPへ(U67) |
| `ROUTE53_FAILOVER` | **退役**(引き戻しは1段に統合済み。`?mode=` の直撃デバッグ専用) |
| `REINVENT_ED` | 差枚 **+1500** または ATセット4到達 |

### ボーナス仕様(2026-08-13 ユーザー決定で変更 / スコアアタック化で再調整)

実機と同じ「**当選 → 揃えろ! → 揃った瞬間に消化開始 → ベルで一気に増える**」構成です。

| | ゴーストボーナス | ゴーストボーナスSP | シャークボーナス |
|---|---|---|---|
| 揃える図柄 | ゴースト7 | ゴースト7 | サメBAR |
| ゲーム数 | **8G** | **1セット6G** / 継続率50% | **6G** |
| 増え方 | ベル約1/1.2で揃い、**1回15枚** | 同左 | 同左 |
| 平均獲得(純増) | 約76枚 | 約101枚(平均1.8セット) | 約57枚 |
| 恩恵(U11) | 消化中の子役でRUSH抽選(総合45%) | 同左(総合85%) | 同左(総合12%) |
| 非当選時 | サミット会場(高確)スタート | 同左 | 同左 |

> 2026-08-14 のバランス調整で、初当りを絞ったぶん**ボーナス単体の価値**を上げました
> (4G/6G/1セット5G → 6G/8G/1セット6G)。RUSH に行けなかった回でも「引けてよかった」と
> 思える量にするためです。消化G数を変えると子役契機のRUSH当選率も一緒に動くので、
> `src/data/rushes.js` の `bonusMult` を必ず引き直してください(検算式はファイル冒頭)。

- 入賞待ち中は**通常時の小役テーブル**のまま。小役が成立したゲームは小役優先で揃わず、
  **ハズレのゲームだけリールが対応図柄を自動で引き込みます**(目押し不要)。通常時のハズレは約48%なので**平均2.1Gで揃います**
- ボーナス中だけベルが 7枚 → **15枚**。通常時のベルは 7枚です(U63 でコイン持ちの調整のため 8枚から変更)
- レア役はボーナス中の方が濃い(ボーナス中の合計 1/4.7 / 通常時 1/6.17)。
  ボーナス中のテーブル(`BONUS_FLAGS`)は **U63 でも据え置き**なので、
  ボーナス→RUSH の当選率(12 / 45 / 85%)は通常設定でも甘スロでも同じです
- 旧仕様(BIG 50G・REG 30G の固定純増方式)の値は `src/data/modes.js` の
  `BONUS_SPECS.originalSpecs` に、旧名は `renamedFrom` に残してあります

### ゲームフォーマット: 100回転スコアアタック

本機は**1プレイ100回転**で終わるスコアアタックです。通常時・CZ・ボーナス・RUSH・
派生ゾーンを問わず、レバーONした回数を通算で数えます。

- 100回転を使い切ると、**まだ消化していない権利を枚数へ換算してクレジットへ加算**します
  (残存価値の買い取り)。「99回転目にボーナスを引いて0枚で終わる」が起きません
  - 買い取るもの: ボーナス残G × 純増、RUSH残G × 現在の純増、RUSH確定を持っていればRUSH1回ぶん、
    入賞待ちなら**ボーナス1回ぶん丸ごと**
  - 買い取らないもの: まだ引いていないセット継続抽選、CZの突破期待値(所有していない権利のため)
- スコア = そのセッションの差枚(買い取り込み)。`R` または `↑` で何度でも挑戦できます

> 増えたぶんの相殺は **CZ突破率ラダーを一律 0.77倍**(加重平均 41.3% → 33.6%)で取っています

>

>   薄くなったぶんは初期台数を約2.4倍・通算上限を 22 → 52G にして**ゲーム数で返して**います
> - **擬似連の復活**。確定役をCZへ直結させると本前兆が走らなくなり擬似連が構造的に消えるため、
>   短い移行前兆を挟む形にしたうえで、本前兆側の擬似連の重みを 10 → 36 に上げました
>   (実測 5.4セッションに1回 → **2.7セッションに1回**)
> - ボーナス中のベル **15 → 18枚**(純増 8.45 → 10.60枚/G)。
>   AS が「長い×軽い」になって100回転で連鎖できる回数が減ったぶんの、上位1%の補填です

> **2026-08-15(U63)レア役の基準をさらに一段UP**
> ユーザー指示「**通常モードを、いまの甘スロ相当にしてほしい**」を受けて、
> 通常時のレア役を **U48 のさらに2倍(従来比4倍)= 合計 1/6.17** にしました。
> 甘スロ(`?ama=1`)はそこから更に2倍の **1/3.1** なので、
> 「新しい通常設定より、甘スロはもっと甘い」という関係は保たれています。
>
> レア役はこの台のほぼ全システムの契機なので、出現率だけを倍にすると初当りも出玉も倍になります。
> そこで U48 と同じく **レア役1回あたりの変換率を絞って相殺**しました
> (CZ当選 0.5倍 / ステージ昇格 0.7倍 / ステージの毎G抽選 0.54倍 / フリーズ率 0.5倍 /
> RUSH の上乗せは**非確定役だけ** 0.5倍 — サメ揃い・ゴースト揃いは据え置き)。
> さらに、
> - **Well-Architected CZ 9G → 7G**・**Aurora RUSH 8G → 7G**(レア役比例で伸びるものは「長さ」で相殺)
> - **通常時のベル 8枚 → 7枚**(レア役の払出が増えたぶんコイン持ちが伸びるのを戻した)
> - **天井 75G → 78G**(中央値だけが浮いたのを戻した。上位1%は1枚も動かない)
>
> 結果、**レア役に出会う回数だけが倍**になり、初当り・平均・上位1%・機械割はすべて目標レンジ内です。

>   ゲーム数が伸びる AS と Aurora には通算ゲーム数の上限(U72 で AS は 52G / Aurora 15G)を入れて、
>   青天井に伸びる尻尾を構造的に断ちました。
> - 上振れは「1回の大当たり」ではなく **連チャン** で作ります。U67 でその作り方を
>   「引き戻しに何度も成功する」から **「引き戻しは通りにくいが、通ったら上位ボーナス」**
>   へ組み替えました(引き戻し 82% → **55%** / 復帰先 ゴーストボーナス → **ゴーストボーナスSP**)。
> - 上位1%が 1,678 → 約1,300枚 に下がっているのは意図した結果です。100回転に入る RUSH は
>   どんなに引いても4〜5回が限界なので、RUSH 1回を800枚で頭打ちにすると
>   上位1%は約1,300枚が算術的な天井になります(詳しい理由は `scripts/sim.mjs` の `TARGET`)。

#### RUSH は4種類(2026-08-14 / U11)

RUSH突入の基本経路は **ボーナス中に子役を引けたらRUSH抽選**です。
引くたびにチャンスが来るので、ボーナス消化そのものが参加型になります
(強い役ほど当選率が高く、総合の突入率は従来の `atRate` と同じ 12% / 45% / 85%)。

当選したRUSHは4種類あり、**伸びる軸が1本ずつ違います**。

| RUSH | 軸 | 中身 | 1回の価値(設計 / 実測) | 中央値 / p99 | 振分 |
|---|---|---|---|---|---|
| オートスケーリングRUSH | ゲーム数 | **EC2の台数 = 残りゲーム数**(常に同じ値)。**レア役**でオートスケール(弱チェ+1台 … サメ+6台 / ゴースト+11台)。純増は**15枚**固定(U72)・初期 平均18.6台・**通算52Gで頭打ち** | 335枚 / 334枚 | 270枚 / **780枚** | 50% |
| CloudFront RUSH | 直接払い出し | **18G固定**。毎ゲーム**95%**でクレジット払い出し(**5〜50枚**・うち90%は5〜20枚)+ **レア役**で確定クレジット(弱チェ10 / 強チェ30 / サメ・ゴースト50枚)。**1回の払い出しは必ず5〜50枚**(U67) | 283枚 / 281枚 | 279枚 / **405枚** | 25% |
| Aurora RUSH | 純増 | **レア役**でACU(純増)がスケールアップし、同時に残りゲームも +1G。**ACU 30 → 最大70**・初期7G・**通算15Gで頭打ち** | 342枚 / 306枚 | 282枚 / **679枚** | 23% |
| ヒーローRUSH | プレミア | 5G固定。**毎ゲーム 50% で 50枚**(U76)+ **レア役**で +α(強チェ30 / サメ300 / ゴースト500枚) | 144枚 / 140枚 | 130枚 / **710枚** | **2%**(実測5.7%) |

> 設計値と実測がずれるのは、100回転を使い切ってRUSHが打ち切られる回があるためです
> (打ち切りぶんは残存価値の買い取りでスコアへ戻ります)。
>
> ヒーローRUSHの実測が振分2%より高いのは正常です。プレミア契機
> (レバーONフリーズ / ボーナス中のゴースト揃い)は専用の振り分け(ヒーロー 1/4)を
> 引くため、そのぶん上に出ます。
>
> **2026-08-15(U76)ヒーローRUSHは「瞬発プレミア」へ**: 毎ゲームの抽選を
> **80% × 70枚 → 50% × 50枚** に半減しました(骨格 56 → 25枚/G)。
> 1回の平均は 289 → **144枚** で4種の中では一番軽くなりますが、
> **中央値130枚に対して p99 は 710枚**(倍率5.5倍は4種で最大)で、
> サメ揃い・ゴースト揃いを1回引けたゲームだけで 350〜550枚が出ます。
> 「安心して300枚」から「**5ゲームで振り切る一発勝負**」へ役割を変えた調整です。
>
> **オートスケーリングRUSH の不変条件**: `state.units === state.remaining`。
> 台数は「いま何台動いているか = あと何ゲーム回せるか」であって、
> 通算ゲーム数(`state.total`)や伸ばした量(`peakUnits` / `addedUnits`)とは別物です。

- どのRUSHも消化しきると **ホットスタンバイ(引き戻し55%)** へ落ちます。
  成功すると復旧の**ゴーストボーナスSP**(RUSH当選85%)へ戻るので、
  **RUSHの後にもう一度RUSHへ入れる確率は約47%**。
  U67 で「82% でよく戻る × ふつうのボーナス」から
  **「55% で戻りにくい × 最上位ボーナス」**へ組み替えました(復活したらラッキー)
- レバーONフリーズの恩恵は「ゴーストボーナスSP + RUSH確定 + プレミア振り分け(ヒーロー1/4)」
- 派生ゾーン / Serverless RUSH 昇格は **オートスケーリングRUSH からのみ**(AWSのスケーリングという題材が一番近いため)
- 数値はすべて `src/data/rushes.js`。`node scripts/sim.mjs --session=2000 777` の
  「RUSH 4種」表(平均獲得 / 平均G / 振り分け)を見ながら調整します

## 演出システム(Phase 3)

演出は**データ定義**で追加します。コードを書かずに `src/data/scenarios/*.js` へ
オブジェクトを1つ足すだけで新しい演出が入ります。

```js
{
  id: 'cz_cw_alarm_entry',
  when: { event: 'modeEnter', enterMode: ['CZ'] },   // 発動条件
  weight: { FREE_TIER: 100, default: 10 },           // 候補が competing したときの取り合い比率
  chance: 0.3,                                       // 単独候補でも間引きたいとき(ガセ予告など)
  duration: 3200,
  cues: [
    { at: 0,    layer: 'overlay', action: 'flash', params: { color: '#ff3b30', ms: 300 } },
    { waitFor: 'stop3', after: 200, layer: 'lcd', action: 'anim',
      params: { anim: 'cw_alarm_result', result: '$state.success' } },  // ← 遅延バインド
  ],
}
```

- **キューは3種**: `at`(時間)/ `waitFor`(イベント待ち)/ `waitFor` + `after`
- **`$` 参照**: `'$state.success'` や `"$continued ? 'a' : 'b'"` が実行時に解決されます
- **アクション**は `layer.action` で `src/staging/actions.js` のレジストリを引きます。
  新しい種別が要るときだけ1行足します
- **演出用の乱数はゲーム用と分離**しています。シナリオを増減してもゲームの抽選結果は変わりません
  (`?seed=N` を固定したまま `?nofx=1` と付け外しして同じ出目になることで確認できます)

実装済みの演出は **128件**です(通常時・CZ・ボーナス・RUSH・引き戻し26 / 派生ゾーン20 / 上位AT・ED・積み残し22
/ 前兆13 / 弱中予告20 / 強予告・カットイン14 / ギミック予告13)。
ボーナスは「確定告知+揃えろ指示 → 揃った瞬間の入賞ファンファーレ → 突入カットイン」の3段構成です。
うち多くは**ガセ予告**(期待させて外すもの)で、見た目の熱さと実際の期待度をわざとズラしてあります。

通常時に何かしらの演出が出る割合は、非レア役で **約30%**、レア役で約87%、前兆中は毎ゲーム(100%)です。
強予告(GuardDuty・CloudTrail 等のカットイン系)は約 **1/80G** に抑えてあり、出れば「おっ」となる頻度に調律しています。

### 前兆システム

通常時のCZ・ボーナス直撃・AT直撃の当選は、その場では出さずに **2〜5ゲームの「本前兆」を挟んでから**告知します
([`src/data/zencho.js`](src/data/zencho.js) / [`src/game/modes/freetier.js`](src/game/modes/freetier.js))。
さらに非当選時にも 1/40 で **2〜4ゲームの「ガセ前兆」**が発生し、最終ゲームに何も起きずに終わります。
前兆中は毎ゲーム `paramChange`(`zencho` / `zencho_upgrade` / `zencho_end`)が飛び、
`zn_` プレフィックスの13本のシナリオが SQS 保留・X-Ray エラートレース・CloudTrail の Root User Login といった
「何か起きているかも」の空気を作ります。ガセは最長4ゲームなので **5ゲーム目まで伸びたら本前兆確定**です。

- 前兆中も当選抽選は毎ゲーム引き続けるため、**前兆を挟んでも初当り確率は落ちません**(遅延するだけ)。
  前兆中に当たった場合はガセ→本前兆への格上げで吸収され、当選が握り潰されることはありません
- 演出へ渡してよいのは `step` / `level` だけです。残りゲーム数(`left` / `total`)を画面に出すと
  前兆の長さが割れて「5ゲーム目=確定」の期待度設計が死にます

```bash
cp .env.example .env          # AIVIS_CLOUD_API_KEY / LUNA_MODEL_UUID などを記入
node scripts/generate-voices.mjs --dry-run --char=luna   # 定義チェックのみ(API未呼び出し)
node scripts/generate-voices.mjs --char=luna             # 未生成ぶんだけ生成
```

`assets/voices/` に MP3 と `manifest.json` が出力され、次回起動から自動で読み込まれます。
モード突入時にそのモードで使うセリフだけを遅延プリロードするため、起動は重くなりません。

`.env` は Git 管理外です(リポジトリ直下の `.gitignore` で除外済み)。
セリフを足すときは `scripts/generate-voices.mjs` の `PHRASES` に1件足してから再実行してください。
**既存の file 名は絶対に付け替えないこと**(番号がズレると既存MP3が別テキストとして再利用されます)。

#### 相槌プール(2026-08-15 U71)

同じ場面で毎回同じ声が鳴らないよう、前兆・煽りのセリフは **束(プール)** から1本引きます。
束の定義は `src/data/voicepools.js`、シナリオ側の書き方は次のとおりです。

```js
{ layer: 'voice', action: 'play', params: { pool: 'react', chance: 0.25 } }  // 相槌から1本
{ layer: 'voice', action: 'play', params: { key: 'luna_rush_01', force: true } } // 従来どおりの1本指定
```

| プール | 中身 | 使いどころ |
|---|---|---|
| `react` | おっ? / なになに? / あれ? / ん? / お? / んん? / なんか来てる…? / ちょっと待って? | 前兆・予兆の入り |
| `tease` | これは… / もしかして? / 激アツ? / チャンスかも? / ざわざわしてる… / くるかも… / うずうずする… | 伸びた前兆・強予告の煽り |
| `doubt` | 気のせいかな? / んー… / んん? | ガセ終了の締め |

- 直前に鳴らした key は候補から外れるので、2連続で同じ声になりません
- 抽選は `Math.random`(**演出RNGを1ステップも動かさない**ので出目は変わりません)
- 鳴ったセリフに合わせてルナの表情も数秒だけ変わります(「あれ?」で首をかしげる等)
- プールのセリフは **全部が疑問形**。ガセ前兆にも同じ確率で貼るので、声から当たりは読めません

## ディレクトリ構成

```
awslot/
├── index.html          筐体のDOM構造
├── style.css           筐体・電飾・ボタンのCSS
├── .env.example        キャラ音声生成に使うAPIキーのテンプレート
├── assets/
│   ├── symbols/        絵柄PNG(任意)
│   └── voices/         キャラ音声MP3 + manifest.json(生成物・任意)
├── scripts/
│   ├── serve.mjs           開発用の静的サーバ
│   ├── sim.mjs             ヘッドレス自動試行(バランス検証)
│   ├── shot.mjs            見た目確認用スクリーンショット撮影(before/after 比較)
│   ├── measure-bezel.mjs   液晶窓と筐体アートの左右余白を実測(ベゼルの対称性)
│   └── generate-voices.mjs キャラ音声の一括生成
└── src/
    ├── main.js         初期化とゲームループ、音の配線
    ├── engine/         ゲーム非依存の基盤(loop/input/rng/eventbus/layers/assets/timeline/audio/voice)
    ├── game/           ゲームロジック(描画も演出も一切知らない)
    │   └── modes/      モードごとの継続管理
    ├── data/           抽選テーブル・リール配列・効果音プリセットなどのデータ定義
    │   └── scenarios/  演出シナリオ定義(ここに追記するだけで演出が増える)
    ├── staging/        演出システム(director/actions/anims)
    └── render/         描画(Canvas / DOM)
        └── chars/      キャラのプロシージャル描画(Kiro / ジョージ)
```

**依存方向の原則**: `game/` は `render/` も `staging/` も一切 import しません。
ゲーム → 演出は `EventBus` の一方向のみで、演出側からゲーム状態を書き換えることはありません。
